## Findings

### Strengths

- **Clean manifest ↔ graph ↔ phase alignment.** Every dependency edge in the mermaid block matches the manifest table; every subtask's phase is exactly `max(phase of dep) + 1`; no subtask depends on a higher-numbered id. This is unusually tidy for a 10-subtask spec.

- **Zip safety is grounded.** Subtasks 01/03 correctly point at the concrete `service/agent_plugins.py` constants (`MAX_ZIP_BYTES = 1_500_000`, `MAX_UNCOMPRESSED_BYTES = 4_000_000`, `MAX_FILES = 80`, allowed suffix set) rather than reinventing them; the `.glsl` addition is the only real change.
- **Consent stamp reuses existing infrastructure.** The stamp payload extension for shader/backend/collector sha256 fits cleanly into today's `service/plugins.py::consent_stamp` — no new consent store to build.
- **Deterministic pack is spelled out.** Subtask 03 pins date_time to `(1980, 1, 1, 0, 0, 0)`, sorts lexicographically, and requires `ZIP_DEFLATED` at a fixed compression level so re-packing the same source tree produces byte-identical output — that is the right hook for CI drift detection in subtask 09.

## Recommendation

The spec is **structurally sound** — the manifest, mermaid graph, and phase assignment are internally consistent and the requirements match the overview. The bulk of the work is a lateral refactor over `service/agent_plugins.py` and `service/plugins.py` and is entirely feasible with the existing WebGL / esbuild / pytest tooling. But it is **not ready to execute as-is**: two subtasks reference files that do not exist (`web/src/app/host.ts`, an `engine` switch in `scene.ts`); the migration story for existing user data is missing; `tests/test_agent_plugins.py` will break subtask 10's DoD; and phase 4 has real merge-conflict paths between 07 and 08. Address the eight HIGH findings (and ideally the MEDIUMs) before running `/z-spec-execute` — most are small, mechanical edits to the spec files, not scope changes.

Not all risk went away — a few items are pushed into execution rather than eliminated:

1. **Deterministic pack across contributor machines** still depends on matching zlib versions. Mitigation is a CI reproduce check on pinned Python; contributor-side diffs will still surface as CI failures until they update.
2. **First-startup migration** silently drops `skills/` and `ui/` folders from any pre-existing lan-pulse-style install. The DoD requires a loud log line but the operator has to notice.
3. **Rollback flag** doubles the surface area for one release (both scanners live). If a bug lands in the new code path, users may end up running the legacy path in production for longer than intended. Track flag retirement explicitly in a follow-up spec.
4. **`api_draft_plugin` I/O change** is a wire-shape break for any agent that already calls it. The old handler is retired without a translation layer; make sure `docs/agent.md` calls this out.
5. **`plugin zip` deprecation alias** must actually be removed after one release; leave a follow-up ticket.
6. **Shader uniform contract enforcement**: subtask 07's compile-time reject is regex + WebGL introspection. A crafted GLSL source that hides a `uniform` behind a preprocessor macro could bypass. Not a security boundary (consent stamp already gates review), but call it out.
7. **Cross-platform tests** — the migration test fixture assumes POSIX-style paths and a Unix-shaped `~/.zoto-viz/`. Windows support is out of scope but should be flagged in `docs/install.md`.
